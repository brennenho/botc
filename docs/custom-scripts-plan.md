# Custom script uploads

**Proposed first release.** A Storyteller downloads a JSON file from the official Script Tool, chooses **Upload script** during game creation, previews the characters, and opens a grimoire. Joining players get the same character sheet from the game code. The first release covers scripts assembled from published characters, including experimental characters. The issue leaves support for author-defined homebrew characters open. [Issue 36, More Scripts](https://github.com/brennenho/botc/issues/36)

## What the importer needs to understand

In the official Script Tool, an author selects characters, can arrange them within their groups, and can give the script a name and author. **Download JSON** and **Copy JSON** serialize the same roster. The player and Storyteller sheet downloads are for printing. An uploaded roster lists the characters that *could* be in play. The Storyteller chooses which ones to deal after creating the game. [Official Script Tool](https://script.bloodontheclocktower.com/) · [TPI’s custom script guide](https://bloodontheclocktower.com/pages/custom-scripts)

The current exporter writes a JSON array with a `_meta` object followed by character entries. Published characters use string IDs such as `"villageidiot"`. Older files can use `{"id":"villageidiot"}`. Metadata is optional in the interchange format and may include custom night orders and Bootlegger rules. A full object that supplies a character’s own name, team and ability is a character definition. Treating that object as a plain ID could discard the author’s rules. [TPI script schema](https://github.com/ThePandemoniumInstitute/botc-release/blob/main/script-schema.json) · [TPI metadata documentation](https://github.com/ThePandemoniumInstitute/botc-release#custom-scripts)

Experimental characters are published by TPI for use on custom scripts and can change as TPI updates them. In this checkout (`ec75761`), the role data contains **181** records. The runtime catalog and local token art cover **87** from the base three. Another **71** have source edition `carousel` (30 Townsfolk, 11 Outsiders, 15 Minions, 10 Demons, 3 Travellers and 2 Fabled). The remaining 23 have source edition `fabled` or `loric`. Use the character’s team to decide how to display or assign it. For example, Ferryman is both a Carousel entry and a Fabled. [Experimental roster](https://wiki.bloodontheclocktower.com/Experimental) · [TPI toolmaker data and artwork](https://release.botc.app/resources/) · [Checked-in catalog](../src/lib/game-data/catalog.ts)

## Implementation sequence

### 1. Separate the game’s script from the official character catalog

Introduce a script definition with a display name, optional author, and ordered character IDs. Resolve a built-in edition or an uploaded definition through the same helpers for character lookup, team grouping and display. Keep the three built-in edition IDs for their routes and existing games. Give official characters a separate source-edition type. Define the four resident teams explicitly so expanding the catalog cannot put Fabled or Loric into a seat, a bluff or a population count. [Game types](../src/lib/game-data/types.ts) · [Character sheet definitions](../src/lib/game-data/character-sheet.ts)

Extend the asset sync to read roles, night order and jinxes from the same upstream revision. Generate the runtime and public copies from that input and fetch the missing character artwork and generic custom-script logo. Keep the source revision with the vendored data and check that each supported ID resolves to artwork. Include `remindersGlobal`, which supplies tokens such as the Marionette’s marker. Reconcile the existing Drunk and Philosopher supplements so their copy counts stay correct. [Asset sync](../scripts/sync-assets.mjs) · [Reminder inventory](../src/lib/reminders.ts) · [TPI resources](https://release.botc.app/resources/)

### 2. Build one importer for preview and server validation

- Accept a local `.json` file with string IDs, legacy ID objects, or a mixture. Preserve within-team file order. Accept an omitted metadata entry or a blank title and display “Untitled script.” Use the schema’s 5–201 array-entry bounds and enforce a documented byte limit in both the file picker and the API. A 25-character target or a fixed team distribution would exclude published scripts.
- Preserve the name, author, plain-text Bootlegger rules and explicit first-night and other-night sequences. Validate night-order references against the uploaded roster and the system entries allowed for that night. Use the bundled custom logo for the first release. Give the preview a short notice when optional presentation fields are omitted.
- Report malformed JSON, duplicate metadata or roster entries, unknown IDs and inline homebrew definitions with the offending entry or position. Let the Storyteller replace the file before creating the game. A duplicate entry in a *script* is separate from assigning multiple copies of a character during *setup*. [TPI script schema](https://github.com/ThePandemoniumInstitute/botc-release/blob/main/script-schema.json)

### 3. Persist the script with the game

Extend `POST /api/games` to accept the existing edition payload or a custom upload. Parse the custom input on the server. In a new migration, allow a custom edition discriminator and add a nullable `games.custom_script` JSONB column. Constrain the combinations so custom games require a definition and built-ins retain their edition IDs. Store the normalized roster and supported metadata in the same `botc_create_game` transaction that creates the seats. Existing cleanup then removes the upload with its game. Deploy the additive database change first and preserve the existing RPC call and service-role permissions during rollout. [Create route](../src/app/api/games/route.ts) · [Validation](../src/lib/server/validation.ts) · [Current schema and RPC](../supabase/migrations/20260812000000_initialize_botc_schema.sql)

Include the public script definition in both snapshot projections on create, join and refresh. Keep actual assignments, bluffs and reminders in their existing private paths. Validate custom-game mutations against the game’s roster and the relevant token or seat type after loading the game. Preserve the existing option to add a cross-edition Traveller. Apply the same rules in seat normalization so saving a valid experimental role cannot clear it. [Server store](../src/lib/server/store.ts) · [Seat normalization](../src/lib/server/seat-normalization.ts) · [Player seat projection](../src/lib/player-seat-view.ts)

### 4. Use the uploaded script throughout play

| Surface | Required behavior |
| --- | --- |
| Game creation and reference | Add the upload beside the built-in choices. Preview the title, author, team counts and character list before **Open Grimoire**. Use the resolved title and roster in the toolbar and both in-game sheets. Group listed Travellers separately and show Fabled and Loric as Storyteller rules. |
| Distribution, bluffs and reminders | Draw resident choices from the script, allow listed Travellers in Traveller seats, and filter bluff options to eligible characters. Feed the same roster into the reminder picker and deal mutation. Preserve the existing Drunk cover-token workflow. |
| Setup exceptions | Use official selection flags such as `bag-duplicate` to identify repeatable roles. Support repeated seat assignments such as Village Idiot (up to three) and Legion (a majority). Huntsman requires a Damsel in play. Where the setup helper cannot evaluate an interaction, show the ability and allow manual setup. Suppress misleading legality claims and the arbitrary random fallback. For concealed roles such as Marionette, let the Storyteller use a cover character and a private marker. Check the joining player’s role **and alignment** display for accidental reveals. |
| Night order | Start with TPI’s ordered nightsheet filtered to the roster, including applicable system steps. An explicit order in the upload takes precedence for its night. Use official wake text wherever the app lacks a hand-authored action. Include assigned extra Travellers in the in-play view and distinguish individual seats when multiple copies wake. Let the Storyteller run applicable Fabled and Loric steps without assigning them seats. |
| Jinxes | A jinx is a special rule for a particular pair of characters. Show each applicable pair and its official wording on both reference sheets whenever both characters are on the **script**, even before roles are dealt. This lets players read the Djinn rules without revealing who is in play. |

Start with the existing [role distribution dialog](../src/components/storyteller/role-distribution-dialog.tsx), [deal mutation](../src/lib/game-state/mutations.ts), [setup assessment](../src/lib/game-data/setup.ts), [night order](../src/lib/game-data/night-order.ts) and [jinx data](../public/assets/data/jinxes.json). The relevant rulings are documented for [Village Idiot](https://wiki.bloodontheclocktower.com/Village_Idiot), [Legion](https://wiki.bloodontheclocktower.com/Legion), [Huntsman](https://wiki.bloodontheclocktower.com/Huntsman), [Marionette](https://wiki.bloodontheclocktower.com/Marionette) and [Djinn](https://wiki.bloodontheclocktower.com/Djinn).

## Release checks

1. **Published exports.** Download *No Greater Joy* and *One In One Out* from TPI’s linked Script Tool pages as fixtures. The first should preview 11 residents from across the base editions and run at five or six players. The second should preview 25 residents plus Spirit of Ivory. Its Village Idiot token should resolve, and the Spy–Ogre jinx should appear on an empty grimoire’s reference sheet. [TPI’s published scripts](https://bloodontheclocktower.com/pages/custom-scripts)
2. **Importer and game-data tests.** Cover legacy and mixed ID forms, missing metadata, malformed and oversized files, unknown IDs, inline definitions, explicit night-order overrides, global reminder counts and duplicate seat assignments. Compare built-in character sheets and night orders to their existing expectations.
3. **Database and API tests.** Create each game type through its supported payload. Check that rejecting an upload leaves no game or seats, a failed custom mutation preserves the previous snapshot, and existing game rows still load. Verify service-role-only RPC execution and that player responses contain the public roster and permitted seat details.
4. **Two-browser acceptance test.** The Storyteller uploads, previews, creates, deals an experimental role, sets a bluff and places a reminder. A player joins on a second device, reads the same sheet, and sees their intended private reveal. Assert that their API response omits the bluff, reminder and other residents’ assignments. Refresh both sessions and verify roster, night order and privacy. Repeat the create-and-join smoke test for each built-in edition.

## Second milestone for homebrew characters and icons

A homebrew character travels in the script as an inline definition. For example, this single entry supplies everything the grimoire needs to display the character on a sheet and assign it to a player. The URL is illustrative. [TPI homebrew format](https://github.com/ThePandemoniumInstitute/botc-release#homebrew-scripts)

```json
{
  "id": "bellkeeper",
  "name": "Bellkeeper",
  "team": "townsfolk",
  "ability": "Once per game, during the day, you may learn how many Minions are alive.",
  "image": "https://example.org/clocktower/bellkeeper.png"
}
```

1. **Import and store the definition.** Extend the shared parser to accept the four required fields above (`id`, `name`, `team`, `ability`) alongside official IDs in the same file. Keep supported optional fields for icon variants, reminders, global reminders, wake positions and text, setup and jinxes. Save definitions with the game’s script and return them with the public character sheet. Track whether an entry came from the official catalog or from the upload so a homebrew character named `"drunk"` cannot accidentally trigger built-in Drunk handling.
2. **Resolve the character wherever it appears.** Use the game’s character lookup for server validation, seat assignments, bluffs, reminders, night order, reference sheets and player reveals. For each night, use the script’s explicit order if supplied. Otherwise merge homebrew wake positions with the official night order. Show author-written abilities and setup instructions for the Storyteller to adjudicate.
3. **Render the supplied icon.** Official ID entries use bundled art. For homebrew entries, the optional `image` field can hold a single URL or up to three URLs. A regular character can supply its usual and flipped alignment icons. A Traveller can supply neutral, good and evil icons in that order. A shared character sheet uses the default or neutral icon. An assigned token may use an alignment variant only when that viewer can see the alignment. Load supported HTTPS URLs directly in the browser. If a variant is missing or fails to load, try the default icon, then a bundled generic team token. The character’s name and ability stay available even when the image host is offline. [Official image-field schema](https://github.com/ThePandemoniumInstitute/botc-release/blob/main/script-schema.json) · [Shared token artwork component](../src/components/grimoire/role-artwork.tsx)
4. **Verify with a mixed script.** Import an official ID, a homebrew Townsfolk with one icon and a Traveller with three. Assign and reveal them, place a custom reminder, and refresh both clients. Check the neutral Traveller art on another player’s device, fallback behavior for a missing or broken image, and two simultaneous games giving the same custom ID different names and abilities.
